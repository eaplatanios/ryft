# Contributing to `ryft`

Thanks for your interest in contributing! This file is the developer-facing entry point — it covers
how to set up the toolchains, build and test the workspace, work on the documentation site, and add
new runnable examples. For deeper code, documentation, and testing conventions, see
[`AGENTS.md`](AGENTS.md) — it is the authoritative style guide for this repository.

## Prerequisites

- **Rust:** the toolchain pinned by [`rust-toolchain.toml`](rust-toolchain.toml). `rustup` will pick
  this up automatically.
- **Platform / accelerator toolchains:** these are only required if you are building the corresponding
  backend. See the per-crate READMEs for details:
  - [`crates/ryft-xla-sys/README.md`](crates/ryft-xla-sys/README.md) — XLA artifacts and supported
    platforms.
  - [`crates/ryft-pjrt/README.md`](crates/ryft-pjrt/README.md) — PJRT bindings.
  - [`crates/ryft-mlir/README.md`](crates/ryft-mlir/README.md) — MLIR bindings.
- **Node.js 20+ and npm:** required if you are working on the marketing surface of the
  documentation site (the Astro project under [`docs/`](docs/)).
- **mdBook:** required if you are working on the user guide (the mdBook source under
  [`docs/book/`](docs/book/)). Install with `cargo install --locked mdbook`.

## Building, testing, and formatting

The canonical workspace commands (see [`AGENTS.md`](AGENTS.md#commands) for the full list):

```sh
cargo build                  # build all crates
cargo build -p <crate>       # build one crate
cargo check                  # type-check all crates
cargo test                   # run all tests
cargo test -p <crate>        # run one crate's tests
cargo fmt                    # format all crates
```

Prefer scoping to a single crate (`-p <crate>`) while iterating to reduce build time and avoid
cross-crate churn.

## Documentation site

The documentation site at <https://ryft.dev> is composed of three independently-built surfaces that
all live in the [`docs/`](docs/) directory and ship as a single GitHub Pages deployment:

| Surface | Tool | Source | Served at |
|---|---|---|---|
| Landing + marketing + examples | Astro + Tailwind + Solid.js | [`docs/src/`](docs/src/) | `/` |
| Long-form user guide | mdBook | [`docs/book/src/`](docs/book/src/) | `/book/` |
| API reference | rustdoc | (autogenerated by docs.rs) | <https://docs.rs/ryft> |

The Astro site and the mdBook are built separately in CI, then stitched together so the mdBook
output sits under `/book/` on the same domain. See
[`.github/workflows/docs.yaml`](.github/workflows/docs.yaml) for the exact orchestration.

### Working on the Astro site

```sh
cd docs
npm install
npm run dev      # live-reload preview at http://localhost:4321
npm run build    # one-shot static build into docs/dist/
npm run check    # type-check the Astro project
```

`docs/dist/`, `docs/node_modules/`, `docs/.astro/`, and `docs/book/book/` are git-ignored.

### Working on the mdBook

```sh
cd docs/book
mdbook serve --open   # live-reload preview at http://localhost:3000
mdbook build          # one-shot build into docs/book/book/
mdbook test           # compile-check embedded Rust snippets
```

When iterating on the combined output locally, build the Astro site first and then drop the mdBook
into the same `dist/`:

```sh
cd docs
npm run build
mdbook build book --dest-dir ../dist/book
```

### Adding a new runnable example

Examples live as Cargo examples under [`crates/ryft/examples/`](crates/ryft/examples/) so that
`cargo run -p ryft --example <name>` Just Works. Each example is also surfaced on the site so
readers can see the source without having to clone the repo.

1. Create `crates/ryft/examples/<name>.rs` with a brief `//!` doc comment explaining what it does
   and how to run it.
2. Verify it builds and runs:

   ```sh
   cargo run -p ryft --example <name>
   ```

3. Create `docs/src/pages/examples/<name>.mdx` that imports the source at build time via Vite's
   `?raw` suffix:

   ```mdx
   ---
   layout: ../../layouts/Layout.astro
   title: <Human-readable title>
   description: <One-line summary for previews and search>
   ---

   import { Code } from 'astro:components';
   import src from '../../../../crates/ryft/examples/<name>.rs?raw';

   <Code code={src} lang="rust" />
   ```

   This guarantees the rendered page never drifts from what Cargo compiles.

4. Add a card for the new example on
   [`docs/src/pages/examples/index.astro`](docs/src/pages/examples/index.astro).
